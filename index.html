Method and limits

The unit is the duty, not the provision. One provision can carry several duties, and one duty can sit across several provisions.

Named and not named. A sector is named when the text addresses it directly. It is reached without being named when the duty lands on a public buyer, a supplier, or an input it depends on. This run covers a horizontal corporate-reporting file that does not name industry sectors at all — it applies by company size, not by sector — so the sector picker below will legitimately return few or no hits for every sector.

Burden drivers. Seven yes-or-no marks read off the text, shown as the strip on each row: D1 new document, D2 accredited outside verification, D3 approval needed before you proceed, D4 new measurement or data systems, D5 recurring, D6 money attached to failure, D7 you are newly inside the regime altogether.

No euro figures. None are given here except where they are operative text in the file — a threshold that decides who is in scope.

Counts are unweighted. One narrow duty counts the same as one duty reaching thousands of companies. Adding the number of affected companies is the next step and will change the picture.

Two extraction passes. Every duty below was extracted twice, independently, and mechanically checked for verbatim source text and driver/direction consistency. Rows where the two passes disagreed were resolved by editorial judgement and are called out in the accompanying report, not silently merged.

Rule as a diff. Each row states the prior rule and the new rule side by side, plus who gains or loses the obligation (the affected-population delta), rather than asserting a weight in isolation. Weight (Relief / Burden) is derived from that diff’s nature, not stored independently — a duty removed or narrowed is Relief, a duty created or extended is Burden.

Prior rule, honestly sourced. An amending act carries only the new text. Where this proposal's own recitals describe the rule it is replacing, that description is quoted verbatim and labelled recital — a real quote from this file, but not the original statute's own wording. Where a source document unaffected by this Omnibus states the actual pre-existing rule verbatim, it is labelled sourced — the strongest tier. Where none of this is available locally, it is marked unresolved rather than guessed.

Status: adopted, not pending. A consolidated text of Directive (EU) 2024/1760 confirms this proposal was formally adopted as Directive (EU) 2026/470 of 24 February 2026 — cross-checked verbatim against three of this register's rows. The duties below describe current, in-force law, not a draft that could still change in negotiation. A consolidated text only carries the current wording, though, not what it replaced — so eight CSDDD-side rows still cite this proposal's recitals (or are marked unresolved) for their prior rule, pending an earlier snapshot of the directive.

Two-sided: what you owe and what you can get. Every measure is either an obligation (a duty, read against the seven burden drivers) or an incentive (funding, demand, credit, or protection, read against four value drivers and five access frictions). The tag on each row reads a four-way valence: Burden and Relief for obligations, Opportunity and Loss for incentives, derived from measure type and direction rather than set by hand. The Omnibus is a reporting and due-diligence simplification file with no funding or demand-creation mechanism in it, so every row here is obligation-side — that is the correct read for this file, not a gap in the model. The infrastructure for incentive rows (value/friction strip, benefit statement, Opportunity/Loss tags) is built and validated; it activates once a file with a benefit side, such as the Industrial Accelerator Act, is extracted.
